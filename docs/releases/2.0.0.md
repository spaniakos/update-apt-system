# updateself 2.0.0

The original APT updater is now **updateself**, a cross-platform updater for
installed system packages and common command-line tools. Both `updateself` and
the shorter `updsf` command are installed; `update.sh` remains a checkout entry point.

## Highlights

- macOS, Debian, Fedora/RHEL, Arch, SUSE, Alpine, Void, Gentoo and Slackware support.
- FreeBSD, OpenBSD, NetBSD and Nix backends.
- Snap, Flatpak and installed tool updates, with ownership-aware handling.
- Explicit Python environment selection and pip updates that respect managed Python.
- Dry runs, selectable components, user separation, failure summaries and locking.
- Git installer/uninstaller, manual pages, completions and GitHub Wiki guides.

## Migrating from the APT script

Run as your normal account. Use `updateself --dry-run` first and `updateself --ask`
to review update commands. `-n` continues to ask; `-y` is consistently the default.
Cleanup and APT dist-upgrade now require explicit options. Root execution no longer
defaults user-level tools to root. Missing optional tools are skipped.

## Choosing a download

Download the package matching your OS, architecture and distribution release.
The portable `updateself-2.0.0.tar.gz` includes the Git/archive installer and docs.
macOS has separate Intel and Apple Silicon installers. BSD packages are target
specific. Nix assets are recipes and build metadata; use the documented flake install.
Homebrew, MacPorts and Gentoo files are generated recipes, not upstream submissions.

Verify downloaded files against `SHA256SUMS`; on Linux, use `sha256sum -c SHA256SUMS`
after downloading all listed assets. On macOS, use `shasum -a 256 -c SHA256SUMS`.
Read `BUILD-REPORT.md` for the exact source revision and expected package matrix.
Tag releases also generate GitHub provenance attestations.

## Package limitations

Packages are not signed by distribution maintainers. The macOS installer is
unsigned and not notarized. Alpine's temporary signing key is only for disposable
CI installation tests; use the Git/archive installer unless you have an appropriate
local trust process. Fedora-built RPMs do not certify every RHEL/SUSE release.
No packages are submitted to external registries or distribution repositories.
